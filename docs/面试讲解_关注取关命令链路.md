# 面试讲解：关注/取关命令链路

> 对应版本：知光 `dev` 分支第四批后端重构

## 1. 30 秒面试说法

原来的关注接口用普通 upsert，每次重复关注都会更新时间并可能再次发送 `FollowCreated`；重复取关也会反复更新，重新关注时事件里的关系 ID 甚至可能不是数据库真实主键。我把它改成幂等命令：先校验不能关注自己和目标用户存在，再用带原状态条件的 SQL 完成状态迁移。新关系由 `(from_user_id, to_user_id)` 唯一键解决并发竞争，只有真正发生 `未关注 -> 已关注` 或 `已关注 -> 未关注` 时才在同一事务写 Outbox。重复请求直接返回目标状态成功，不重复修改计数或发送事件。

## 2. 关注业务链

```text
POST /api/v1/relation/follow
  ↓ JWT 解析当前用户
校验 fromUserId != toUserId
  ↓
校验目标用户存在
  ↓
Redis 令牌桶限流
  ↓
UPDATE following
SET rel_status = 1
WHERE 用户对匹配 AND rel_status = 0
  ├─ 影响 1 行：已取消 -> 已关注
  │    ├─ 查询数据库真实 relationId
  │    └─ 写 FollowCreated Outbox
  └─ 影响 0 行：可能是新关系或已经关注
       ↓
     INSERT IGNORE following
     由 uk_from_to(from_user_id, to_user_id) 仲裁并发
       ├─ 插入 1 行：写 FollowCreated Outbox
       └─ 插入 0 行：已关注，幂等返回 true，不写事件
```

业务表修改和 Outbox 插入都在 `@Transactional` 本地事务内。Outbox 写入失败会抛出异常，关注状态一起回滚。

## 3. 取关业务链

```text
POST /api/v1/relation/unfollow
  ↓ 身份与目标用户校验
UPDATE following
SET rel_status = 0
WHERE 用户对匹配 AND rel_status = 1
  ├─ 影响 1 行：查询真实 relationId，写 FollowCanceled Outbox
  └─ 影响 0 行：本来就未关注，幂等返回 true，不写事件
```

接口返回值表示“是否达到调用者要求的最终状态”，不是“本次是否修改了一行”。因此重复关注和重复取关都返回 `true`；关注命令触发限流时返回 `false`。

## 4. 异步投影链

```text
following + Outbox 同事务提交
  ↓ MySQL binlog
Canal -> Kafka canal-outbox
  ↓ relation-outbox-consumer
按 consumer + eventId 去重
  ↓
幂等更新 follower 投影表
  ↓
更新关注/粉丝 Redis ZSet
  ↓
根据数据库事实重建双方计数
  ↓
成功后提交 Kafka 位点
```

`following` 是关注命令侧事实表，`follower` 是面向粉丝查询的异步投影。投影消费者可能收到重复消息，所以 follower 更新带唯一约束和条件状态更新，计数也从数据库事实重建，不做不可重放的简单 `+1/-1`。

## 5. 并发为什么安全

- 新增关注：数据库唯一键 `uk_from_to(from_user_id, to_user_id)` 是最终仲裁者。多个请求并发插入时只有一个返回影响 1 行，也只有它写事件。
- 恢复关注：SQL 带 `rel_status = 0` 条件。多个请求竞争同一条已取消关系时只有一个能完成 `0 -> 1`。
- 取消关注：SQL 带 `rel_status = 1` 条件。并发取关只有一个能完成 `1 -> 0`。
- 事件生成依据数据库影响行数，不依据请求次数，也不依赖 Redis 锁。
- Redis 只负责限流与读模型，MySQL 才是关系状态的事实来源。

真实 MySQL 并发验证中，12 个客户端同时插入同一用户对，影响行数结果为一次 `1`、十一次 `0`，最终只有一条有效关系。

## 6. 错误语义

- 关注自己：HTTP 400，`RELATION_SELF_FOLLOW`。
- 目标用户不存在：HTTP 404，`USER_NOT_FOUND`。
- Outbox 或数据库异常：事务回滚，统一返回服务异常。
- 重复关注/取关：不是异常，按幂等成功处理。

## 7. 测试覆盖

- 禁止关注自己。
- 目标用户不存在。
- 新增关注产生版本化事件。
- 已取消关系恢复时使用数据库真实关系 ID。
- 重复关注不重复发事件。
- 首次取关发送取消事件。
- 重复取关不重复发事件。
- Outbox 写入失败向上抛出并触发事务回滚。
- 真实 MySQL 唯一键并发竞争验证。

测试包与生产包保持同构，例如：

```text
src/main/java/com/chuanqing/service/impl/RelationServiceImpl.java
src/test/java/com/chuanqing/service/impl/RelationServiceImplTest.java

src/main/java/com/chuanqing/service/CanalOutboxConsumerService.java
src/test/java/com/chuanqing/service/CanalOutboxConsumerServiceTest.java
```

每个测试类只对应一个生产类，避免把多个消费者混在一个无法定位的聚合测试类中。
